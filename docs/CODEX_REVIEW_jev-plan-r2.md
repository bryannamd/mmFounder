### R2-9. 중간 | 계획 4.2·4.7·7.1, van_westendorp.py:158-202

**문제:** 계획이 가져오겠다는 `compute` 함수는 현재 파일에 없다. 실제 함수는 `analyse`다. 7.1은 `read`의 채택 수만 확인하므로 이 연결 오류를 잡지 못한다. `panel.init`은 카드 1장부터 허용하지만 `analyse`는 완전 답이 5개 미만이면 실패한다. Jev 요청을 모두 유료로 마친 뒤 최종 보고서 생성에서 실패할 수 있다.

**제안:** 연결을 `read → analyse → report`로 정확히 적고 보고서까지 생성하는 오프라인 시험을 둔다. 유효 답 1~4장에서는 구매·이유 결과를 보존하고 가격 분석을 ‘표본 부족’으로 생략하는 등 계약을 정한다. 가격 분석 실패가 완료된 답을 무효화하거나 재호출하게 해서는 안 된다. 통화는 기존 `main`의 추론에 기대지 말고 직접 가져오는 함수에 명시적으로 전달한다.

### R2-10. 중간 | 계획 7 전체

**문제:** 새 설계의 주요 성공 경로는 덮지만, 위 실패 경계와 최종 산출물까지는 덮지 못한다. 특히 리다이렉트를 막는 opener를 쓸 계획인데 가짜 `urlopen`만 바꾸면 실제 전송 경로를 가로채지 못할 수 있다. 가짜 함수가 302 오류를 바로 던지는 시험만으로 Authorization을 가진 후속 요청이 없음을 증명할 수도 없다.

**제안:** 기존 7절의 묶음을 유지하며 다음을 보강한다. 시험 건수 목표나 실제 API 호출을 추가할 필요는 없다.

- **지문·초기화:** 동일 ID 카드 내용·seed·통화·변환 버전 변경, 불완전 기존 디렉터리, 체크포인트 없는 답, 현재 카드 밖 답, 손상 답을 모두 요청 전에 거부한다.
- **저장·재개:** 답 교체 전후와 `jev.json` 교체 전후에 중단을 주입한다. 확정 저장된 카드만 건너뛰고, 응답 수신 후 저장 전 중단은 처리 여부 불명으로 남는지 확인한다. ‘4장째 예외’ 대신 몇 장이 확정 저장됐는지를 기대 호출 수의 기준으로 적는다.
- **변환·가격 출력:** 음수·1 초과 확률, 다른 모델, 사다리 역순·무한대, 평탄 구간, 단일 교차 비단조를 검사한다. 실제 `analyse`·`report`까지 연결해 검열·보정 안내, 5장 미만 처리, 통화, 두 집계의 표본 수를 확인한다.
- **전송·비용:** 실제 opener 경계를 대역으로 삼아 529, 재시도 소진, DNS·TLS·타임아웃, 잘못된 usage, 키 부재, 실패 뒤 재개 통계, 누적 예산을 검사한다. 리다이렉트 후속 요청은 0건이어야 한다. 대기에는 숫자형·HTTP 날짜형 `Retry-After`와 잘못된 값의 처리도 포함한다.
- **회귀·산출물:** 유효한 빈 에이전트 이유, 에이전트 답 0건의 `agreement: null`, 두 디렉터리 사용, 최종 JSON·Markdown 생성을 확인한다. 기존 `results.json`뿐 아니라 `answers/`·패널 메타데이터·기존 Markdown도 보존한다. 새 `run` 경로가 모든 산출물 생성까지 완료돼야 성공이다.

## 뺄 것

1. **기존 가격 CLI에 `jev-answers/`를 바로 넘기는 안내.** 검열·보정 정보를 버리는 경로다. 기존 가격 도구를 수정하지 않을 범위라면 Jev 보고 경로 하나로 안내한다.
2. **검열 편향 방향을 일괄 단정하는 문장.** 특히 ‘아래쪽 검열은 PMC를 낮춘다’는 삭제한다. 곡선별 근거 없는 방향 설명보다 경계와 검열 수를 보여 주는 편이 정확하다.
3. **두 번 교차한 곡선 수를 ‘비단조 수’로 부르는 표현.** 탐지 범위를 그대로 둘 경우 ‘복수 교차 수’로 좁힌다.
4. **구매자 순위를 제공한다는 현재 약속.** 1·5절에는 있지만 4.7 산출물과 7절 기대값에는 순위 표가 없다. 별도로 구현할 뜻이 없다면 첫 버전 설명에서 빼고 저장된 `p_buy`와 구간 표까지만 약속한다.

## 확인하지 못한 것

- 요청한 계획·1회차 검토·DESIGN과 세 Python 파일의 관련 경로를 정적으로 대조했다. 위 숫자 배열과 실패 상황은 계약을 설명하는 수작업 반례이며 새 실험 결과가 아니다.
- 새 실험, API 호출, 네트워크 전송, 실제 키 접근, 유료 작업, 기존 시험 실행은 하지 않았다. TypeSafe의 현재 API 스키마·요금·모델 가용성·재시도 문서도 이번 회차에는 외부 확인하지 않았다.
- 2절 실험 원본·반복 로그·당시 요청 본문은 다시 열지 않았다. 실행 구분 설명의 수정은 확인했지만 수치 자체를 재검증한 것은 아니다.
- `jev.py` 구현, 실제 원자적 저장·재개·키 제거, Python 3.8 동작, 변경 뒤 회귀 통과는 확인하지 못했다. 계획에 적힌 시험은 아직 실행 증거가 아니다.
- 확률·순위·가격의 실제 고객 행동에 대한 타당성, 200장 이상이라는 규모의 통계적 의미, 검열 보정의 정확도는 검증하지 않았다.
