    문제: 가격 네 개를 돌려 구매 수가 감소하는지 보는 것만으로 3.5의 축 검증을 충족하지 않는다. 그 절은 별도 에이전트 패널의 같은 조건 쌍과 Δp 방향을 비교하도록 요구한다. 어느 가격 쌍에 어떤 비교 자료를 쓸지 없다. 에이전트의 0명 대 3명도 작은 모의 패널의 결과이며 실제 고객의 방향을 확정하지 않는다. 같은 자료로 축을 고르고 후보를 고르면 확인 결과가 낙관적으로 기울 수 있다.

    제안: 5절은 가격 반응 점검으로 부르고, 3.5 충족 여부는 별도 조건으로 둔다. 비교 쌍·기대 방향·카드·질문 설정을 실행 전에 고정한다. 에이전트와의 방향 일치와 실제 고객에 대한 타당성은 별도로 기록한다. 확인 자료가 없으면 축 검증 미완료로 남긴다.

13. 심각도 높음 | 계획 4·5; `tests/test_jev.py:64`, `:93`, `:163`, `:462`, `:628`, `:962`

    문제: 손계산 기대값과 전송 경계 대역은 적절하지만, 제안한 시험만으로 새 계약을 덮지 못한다. 같은 대역을 workers 1과 3에 넣어 같은 표가 나오는지는 두 실행이 같은 버그를 가진 경우도 통과한다. `reply_for()`는 보낸 질문에 맞춰 응답을 만들므로, 피치만 치환하고 질문 가격을 잘못 보내도 시험이 통과하기 쉽다. 스레드 시험은 빠른 대역만으로 실제 겹침을 보장하지 못한다. 기존 회귀는 sweep의 새 오류 수집 경계를 검사하지 않는다.

    제안: 다음을 5절의 완료 조건에 추가한다. 기대 요청과 수치는 구현 함수로 만들지 않고 고정 입력에서 독립적으로 적는다.

    - 기존 변형 입력이 다른 경우와 불완전 폴더에서 호출 0건, 기존 파일 바이트 보존. 준비 중 중단 후 재실행도 포함한다.
    - `offer`·`offer-r2` 충돌, 중복 가격, 잘못된 기준 이름, repeat/workers의 0·음수, 빈 입력을 전체 전송 전에 거부한다.
    - 가격 두 개와 USD 6.5 사례에서 렌더링한 본문, 구매 질문, 가격 질문, 보기 순서, 저장 지문을 명시된 계약과 비교한다. 지문이 다르다는 검사만으로 끝내지 않는다.
    - 변형 3개·repeat 2·카드 N장의 최초 호출은 `4N`, 완료 재실행은 0건. 중단 후에는 확정 저장되지 않은 카드만 보낸다. 반복끼리는 같은 지문을 유지한다.
    - 기준 실패, 반복 실패, 예산 중단, 일부 카드 누락, 오래된 집계가 있을 때의 상태·분모·비교 생략·종료 코드를 검사한다.
    - 잡음 0, 정확히 3배, 0.5 경계, 양·음 효과 상쇄, repeat 1과 3 이상을 손계산 표로 검사한다. 문구 검사만으로 통계 계약을 대신하지 않는다.
    - 동시 실행을 남긴다면 Event/Barrier로 겹침과 완료 순서 변경을 강제한다. 취소 뒤 신규 전송 중단, 작업별 `stats/checkpoint/inflight` 분리, 다른 작업의 저장 완료를 검사한다. 대역의 작업 식별은 전역 호출 순서에 의존하지 않는다.
    - 실패 응답과 예상 밖 예외에 가짜 키를 넣어 stdout·stderr·작업 기록·집계 파일 어디에도 남지 않는지 검사한다. 전체 예산과 재개 비용도 별도 기대값으로 검사한다.
    - 에이전트 원본 파일 보존과 최종 판정 불변을 sweep 진입점에서도 확인한다. 회귀 건수 158 자체를 완료 기준으로 삼지 않는다.

## 뺄 것

- 첫 버전의 `--workers`, executor, 스레드용 `run(log=...)` 확장을 뺀다. 순차 실행과 기존 재개 기능으로 변형 준비·짝 비교부터 완성한다. 성능 요구가 확인되면 취소·속도 제한·오류 보호 계약과 함께 동시 실행을 추가한다.
- 고정 3배 기준의 자동 통과 판정과 repeat 1의 과거 잡음 대체값을 뺀다. Δp·반복 차이·뒤집힘·작업 상태를 그대로 제공해도 후보 탐색 기능은 남는다.
- sweep 요약의 변형별 IPP·PME 나열은 생략할 수 있다. 개별 결과에는 보존하고, 공통 사다리 계약 전에는 요약의 구매 확률 비교에 집중한다.

## 확인하지 못한 것

- sweep 구현은 아직 없어 새 명령의 실행·취소·파일 경쟁은 검증하지 못했다. 위 지적은 계획과 현재 1단위 구현의 계약을 대조한 결과다.
- 네트워크 호출, 실제 키 파일 접근, 유료 실행은 하지 않았다. 현재 서비스 요금·계정 제한·모델의 실행 간 독립성과 변형별 잡음은 확인하지 않았다. 원격 실험 기록과 HabitNav 에이전트 답의 출처도 별도로 검증하지 않았다.
- 오프라인 확인: `python3 -B`로 `test_jev.py` 73건을 실행해 모두 통과했다. 소켓 연결·DNS와 임시 폴더 밖의 키 파일 열기를 차단했다. 시험은 가짜 키와 임시 사용자 폴더를 사용했다. 계획에 적힌 전체 158건 회귀는 실행하지 않았다.
- 별도 로컬 확인: 9,900원과 19,000원의 질문 변경 13개, 전체 질문 14개, 동일 입력 반복의 지문 동일, 피치 변경의 지문 변경, 잡음 0의 표시 누락을 확인했다. 이 확인은 sweep 구현의 동작 증거가 아니다.
