**제안:** 재시도 가능한 상태/전송 오류와 즉시 중단할 인증·입력 오류를 구분한다. 추가 재시도 수, 백오프 상한·jitter, `Retry-After`, 전체 시간 예산, 중단 시 종료 코드를 명시한다. 5xx는 무조건 재시도하지 말고 정책을 정한다. 성공·실패·재시도 횟수와 확인된 토큰 비용을 구분하고, 불명 과금은 추정치의 한계로 표시한다. 사전 비용은 고정 $0.01이 아니라 실제 입력 크기와 미처리 카드 수 기준으로 안내하며, 사용자가 승인한 한도를 넘기기 전에 중단할 방법을 둔다. 공식 문서도 [429/529 백오프](https://docs.typesafe.ai/api/errors)와 [재시도 헤더·전체 시간 예산·연결 오류 구분](https://docs.typesafe.ai/sdk/python/api/retries)을 제공한다.

### 12. 중간 | 계획 2.1·2.2·2.3·2.4·7 마지막 문단

**문제:** 실험에서 관찰한 범위를 넘어선 해석과 원본 식별 문제가 있다.

- 카페와 교육 앱은 고객·제품·피치가 함께 바뀌었다. 두 예시의 출력 차이를 오퍼 판별 능력의 검증으로 볼 수 없다. 상위 다섯 명 안에 에이전트 구매자 셋이 있다는 결과도 유망한 관찰이지 실제 구매자 순위의 정확성 검증은 아니다.
- 카드별 언어 차이 평균 0.049는 0.5 근처 카드나 ±0.03의 오퍼 차이보다 작다고 보기 어렵다. “거의 바꾸지 않았다”보다 확률 차이와 판정 변경 수를 함께 적어야 한다. 고정 틀 결과는 v1 평균이 v2보다 높으므로, 4.5의 “같은 카드로 다른 오퍼와 비교할 때만 쓴다”는 권고도 현재 근거보다 강하다.
- 단순 일치율은 전부 미구매로 답해도 높다. 에이전트가 3/20명 구매라면 전부 no인 방법도 85% 일치한다. 같은 표본의 2×2 판정표와 구매자 포착 수를 함께 보여 주고, 에이전트를 정답 또는 교정된 확률로 부르지 않아야 한다. 표본 미응답이 있으면 실제 비교 분모도 표시해야 한다.
- 확인 가능한 현재 `exp2-v1/answers` 20장은 평균 확률 0.426, 구매 3명이다. `exp2-v2/answers`는 0.398, 구매 1명이다. 2.1의 일반 문구 행 0.409·4명과 0.396·2명과 일치하지 않는다. 산출물 덮어쓰기 또는 다른 실행을 인용했을 수 있으므로 표가 틀렸다고 단정할 수는 없지만 재현 근거가 고정되어 있지 않다.
- `exp2.py`는 일반 구매 문구·사다리 11단이다. 구현 계획은 유료 대상 고정 문구·12단이다. 현재 자료의 결과를 그대로 합격 오차로 쓰면 변경된 조건과 모델 변동을 회귀로 오인할 수 있다. “가격 답 20장 완성”도 형식 적합성이지 Van Westendorp 측정의 타당성은 아니다.
- 100장 25초·$0.01은 20장 측정의 외삽이다. 읽은 스크립트는 동기 호출을 실제 순회하지만, 전체 혼합 경로의 시간·실패·재시도 비용을 재는 자료는 아니다. 100명 패널 전체가 25초에 끝나는 것으로 읽히지 않게 해야 한다.

**제안:** 표의 각 행을 불변 실행 산출물과 연결하고 카드·피치·질문·모델·변환 설정을 식별한다. 관찰과 일반화를 분리한다. 실제 API 확인은 최종 질문과 사다리를 고정한 뒤의 탐색 확인으로 두며, 결정적 회귀는 저장된 응답 재생으로 검사한다. 새로운 실험을 이번 검토에서 실행하거나 비용을 발생시킬 필요는 없다.

## 뺄 것

1. **15%포인트 차이일 때만 판정을 경고로 보호한다는 장치.** 근거 없는 문턱이며 10%포인트 차이에서도 판정이 뒤집힌다. 방법별 수치는 항상 공개하고 판정 입력을 분리한다.
2. **Jev 구매 횟수 질문과 “8회 이상 = 10회” 환산.** 이번 실험에서 정확성을 확인하지 못했고 기존 횟수 평균의 의미를 바꾼다. 첫 버전에서는 에이전트 횟수만 응답 수와 함께 보여 줄 수 있다.
