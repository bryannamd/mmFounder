## 지적 목록

### 1. 낮음 | skills/founder-consumer/jev.py:457, :465 | 원격 응답 본문 수신 시 최대 크기 제한 미지정

- 문제: `Transport.post()`에서 `resp.read()`와 `e.read()`를 호출할 때 바이트 크기 인자를 지정하지 않고 끝까지 읽습니다.
- 공격 또는 실패 시나리오: 비정상 프록시 환경, DNS 위조, 원격 엔드포인트 장애로 무한 스트림이나 비정상적인 대용량 응답(수백 MB 이상)이 반환되면 프로세스 메모리가 고갈되거나 응답 처리가 멈출 수 있습니다.
- 제안: `resp.read(10 * 1024 * 1024)`(10MB) 및 `e.read(64 * 1024)`(64KB)와 같이 단일 요청 처리 한도를 넘는 크기 상한을 인자로 전달하여 수신하도록 고칩니다.

### 2. 낮음 | skills/founder-consumer/jev.py:402 | 프록시 환경 변수 참조 여부 미통제

- 문제: `make_opener()`가 `ProxyHandler`를 비활성화하지 않고 `urllib.request.build_opener()`를 부릅니다. 이로 인해 환경 변수 `HTTPS_PROXY`, `https_proxy`, `all_proxy`가 존재하면 시스템 프록시를 경유합니다.
- 공격 또는 실패 시나리오: 실행 환경에 의도하지 않은 프록시 환경 변수가 켜져 있으면 외부 API 요청이 해당 프록시로 향합니다. 기본 SSL 검증이 켜져 있어 가짜 인증서를 통한 감청은 차단되지만, 프록시 설정 오류에 따른 연결 실패나 목적지 호스트 메타데이터 노출이 발생할 수 있습니다.
- 제안: 고정 엔드포인트 직접 통신만 허용할 계약이면 `urllib.request.ProxyHandler({})`를 명시 등록합니다. 사내망 프록시 지원이 의도된 동작이면 문서에 환경 변수 반영 사실을 적습니다.
