FAIL: JSON 이스케이프된 키가 stderr·파일·예외 메시지에 남으며, 재생 시험은 평균 확률 황금값의 변화를 검출하지 못한다.

## 1회차 지적별 해소 여부

1. 미해소(부분 해소): `check_reply`·`check_saved`의 원문 값 노출과 기존 두 유출 재현은 해결됐다. 공통 `_scrub`에는 JSON 표현의 키 유출이 남는다(R2-1).
2. 해소: `URLError`의 reset·broken pipe를 `unknown`에 포함하고, 명백한 연결 거부·DNS 실패만 제외한다. 해당 대역 시험도 통과했다(`jev.py:416`, `test_jev.py:824`).
3. 해소: `Contract`가 상태·피치·고정 문구·12개 가격 질문·보기 설명·P001/P002 순서를 독립 상수와 비교한다. 이전의 세 결함 변이를 모두 검출했다(`test_jev.py:432`, `:462`).
4. 해소: 세 분해 표를 독립 기대값과 비교하고, 일치표는 4/3/2/1의 비대칭 표본을 검사한다. 소득 표 오연결·불일치 유형 교환 변이를 모두 검출했다(`test_jev.py:982`, `:1001`, `:1010`).
5. 해소: 답 파일 20개를 실제로 읽는 `Replay`가 생겼다. 변환의 결정성과 가격 도구의 `read → analyse` 결과를 고정 기대값과 비교한다. 평균 황금값 누락은 R2-2에 기록했다(`test_jev.py:1090`).

## 새 지적

### R2-1. 중간: 허용된 키의 JSON 표현은 제거되지 않는다

- 위치: `skills/founder-consumer/jev.py:449`, `:387`, `:825`, `:874`; 허용 조건은 `:442`.
- 문제: `_key_ok`는 큰따옴표를 포함한 출력 가능한 ASCII 키를 허용한다. `_scrub`는 원문과 Python `repr` 표현만 제거한다. JSON이 큰따옴표를 `\"`로 바꾸면 세 표현 모두 일치하지 않는다. HTTP 오류 본문의 키가 `_clean`을 통과하여 `JevError`, `runs[].stopped`, stderr에 남는다. 원문 문자열 검색으로는 놓치지만 JSON 역변환으로 키 전체를 복구할 수 있다. 계획 4.9의 비유출 요구사항에 어긋난다.
- 제안: JSON 문자열 내부 표현인 `json.dumps(key)[1:-1]`도 제거 대상으로 처리한다. 따옴표·역슬래시가 든 가짜 키로 HTTP 오류와 공통 출력·저장 경계의 회귀 시험을 추가한다. 본문 원문 출력을 제거하는 방법도 가능하다.
- 확인한 방법: 기존 `FakeJev`와 임시 패널에 아래 가짜 키를 사용했다. `_key_ok` 통과, 대역 HTTP 401 한 번, 종료 코드 2였다. stderr와 `json.load(jev.json)["runs"][0]["stopped"]`에서 `HTTP 401: ` 뒤의 JSON을 읽자 키 전체가 복구됐다. 별도 `Transport.post`의 `str(JevError)`에서도 복구됐다. stdout에서는 유출을 재현하지 못했다. 네트워크와 실제 키 파일은 사용하지 않았다.

```python
key = 'tsk-fake-review-"quoted-abcdef'  # 가짜 키
body = json.dumps({"echo": key})
assert json.loads(jev._scrub(body, [key]))["echo"] == key
```

기존 키 유출 시험의 `FAKE_KEY`에는 JSON 이스케이프가 필요한 문자가 없다(`tests/test_jev.py:24`). 따라서 기존 시험 통과와 이 재현은 양립한다.

### R2-2. 낮음: 재생 시험에 평균 확률 황금값 검사가 없다

- 위치: `tests/test_jev.py:1121`; 요구사항은 `docs/PLAN_2026-10-27_jev-panel.md:227`.
- 문제: 재생 시험은 구매 카드·이유·플래그·토큰을 비교하지만, 계획에 기록된 평균 확률 `0.3655`를 비교하지 않는다. 임계값을 넘지 않는 구매 확률의 변경은 변환 결과와 모순되지 않아 모든 재생 시험을 통과한다.
- 제안: fixture의 평균 구매 확률을 독립 상수 `0.3655`와 비교한다. 기대값을 `convert`나 `results`에서 다시 계산하지 않는다.
- 확인한 방법: 임시 폴더에 fixture 20개를 복사했다. P001의 `jev.p_buy`만 `0.29`에서 `0.49`로 바꾸자 평균은 `0.3755`가 됐지만 `Replay` 3개가 모두 통과했다. 저장소 fixture는 수정하지 않았다.

재생 시험의 나머지 황금값은 구현에서 다시 계산하지 않는다. 가격 기대값 3,180원·3,180원·11,190원·18,300원과 구매·이유·플래그·48,418토큰은 시험에 직접 적혀 있다. `convert(...) == fixture`는 별도의 결정성 검사다. 임시 사본에서 P020 파일을 삭제하면 재생 시험 3개 모두 실패 또는 오류가 나므로, fixture를 실제로 읽는 것도 확인했다.

## 뺄 것

뺄 것: 없음. 이번 변경에서 추가로 제거할 부분은 확인하지 못했다. 1회차 삭제 권고는 반영됐다.

## 확인하지 못한 것

- 실제 API의 현재 응답·지연·청구액은 확인하지 않았다. 네트워크 호출, 실제 키 파일 접근, 비용 발생은 없었다.
- fixture는 변환된 답 파일이다. HTTP 원문·카드·피치가 없으므로 실제 수집 경위와 요청 지문은 독립 검증하지 못했다.
- 계획 7.7의 실제 에이전트 대조표 1/2/0/17은 재생 시험에 없다. 에이전트 원본 답이 지정 fixture에 없어 재현하지 못했다. 합성 비대칭 표본의 집계 검증은 통과했다.
- Python 3.8 런타임, 실제 SIGKILL, 디스크 장애는 재현하지 않았다.

검증: Python 3.15.0에서 `python3 -m unittest discover -s tests`에 해당하는 전체 157개 시험이 통과했다. 실행 래퍼로 소켓 연결을 차단하고 임시 HOME을 사용했으며 바이트코드 저장도 껐다. 추가 재현은 메모리의 구현 사본·가짜 전송·임시 fixture 사본만 사용했다. `_recover`에는 키가 든 외부 `inflight`를 문자열·객체·목록으로 넣었고, 모두 `A card`로 출력하며 `inflight`를 지웠다. 이 검토에서 새로 작성한 저장소 파일은 이 문서 하나다.
