## 수정 사항에 따른 부작용 및 새 문제 점검

1. 키 유출 경로 점검:
   - stderr 출력: `Transport._show()`는 `self._clean()`을 거친 결과만 출력합니다. `_clean()`은 `_scrub()`을 실행하여 키 원문과 JSON 및 바이트 인코딩 형태를 마스킹합니다. 시험 `SweepKeys.test_what_the_server_says_goes_to_stderr_only`에서 stderr에 키가 노출되지 않음을 확인했습니다.
   - 임시 파일 이름: `prefix=name + "."`, `suffix=".tmp"` 형식을 사용합니다. `name`은 `P001.json`, `jev.json` 등 사전 검증된 고정 파일명이며 무작위 6자리 문자가 결합되므로 키가 파일 이름에 노출되지 않습니다.
   - 오류 문구: `check_ids()`는 ID 문자열 대신 카드 순번 `i`만 출력하며, HTTP 오류도 고정 상태 코드만 사용하여 예외 메시지를 통한 키 노출을 차단했습니다.
2. `_clean` 순서 변경의 안전성 점검:
   - `raw` 전체에 대해 `_scrub()`으로 키를 먼저 치환한 뒤 `[:EXCERPT]`(300자)로 자르고 공백을 정리합니다.
   - 4,096바이트 경계에서 키가 잘렸을 때, 공백 압축으로 인해 잘린 키 조각이 300자 발췌 영역 안으로 당겨져 올라오는 현상을 방지합니다. 키 제거 동작을 약화시키지 않고 안전성을 강화했습니다.
3. `mkstemp`와 `os.replace`의 재개(중단 뒤 재실행) 영향 점검:
   - 쓰기 대상과 동일한 디렉터리에 임시 파일을 생성하고 원자 교체합니다.
   - 작업이 중단되면 예외 처리기에서 임시 파일을 즉시 삭제하므로 디스크에 불완전한 쓰레기 파일이 남지 않습니다.
   - 재개 메커니즘은 온전히 저장된 최종 JSON 파일만 확인하므로 기존 재개 흐름을 깨지 않습니다.
4. 검사 시점 선행 점검:
   - `run()`: `check_ids(cards)`와 `os.path.islink(ad)` 검사는 `api_key()` 호출, `_save(jpath, ...)` 기록, 네트워크 요청 전송보다 앞서 실행됩니다.
   - `sweep()`: `check_ids(cards)`와 변형 폴더 링크 검사는 잠금 파일 생성, 디렉터리 생성, `api_key()` 호출보다 앞서 실행됩니다.
5. 0600 파일 권한의 영향 점검:
   - 동일한 운영체제 사용자가 CLI와 에이전트를 실행하므로 소유자 읽기 및 쓰기 권한(0600)으로 정상 작동합니다. 타 사용자에게 결과 자료가 노출되는 위험을 줄이고 기존 사용 흐름을 유지합니다.
6. 계획 문서 13절 판단의 타당성 점검:
   - L2(커밋 메일), agy A2(프록시 환경 변수), agy A3(1단위 재읽기)를 수용하지 않거나 범위 밖으로 둔 근거와 5가지 '보장하지 못하는 것' 설명은 모두 기술적으로 타당합니다.
