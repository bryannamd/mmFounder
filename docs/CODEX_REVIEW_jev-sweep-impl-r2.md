## 새 지적 목록

두 건 모두 기존 비교 단계에 남은 결함이다.

### R1. 중간 | skills/founder-consumer/jev.py:1103 | 가격 분석이 검증하지 않은 파일까지 집계한다

문제: `_finished()`가 검사한 `got`은 구매 확률·플래그 집계에만 쓰인다. `_summary()`는 `vw.read()`로 `jev-answers/*.json`을 다시 읽는다. 이 함수는 현재 카드 ID나 Jev 지문을 검사하지 않는다. 자식 반환 뒤 추가된 다른 카드의 가격 답이 IPP·PME에 섞여도 상태는 `done`이다. 같은 표에서 구매 확률은 6장, 가격은 7장을 사용하게 된다. 1회차 지적 3의 동일 카드 집합 사용 요구가 남았다.

제안: `_summary()`의 가격 입력도 이미 검증한 `rows`에서 `vw.KEYS` 순서의 가격 튜플로 만든다. 이 경로의 디렉터리 재읽기를 제거한다. 집계 직전 다른 카드 파일까지 거부할 계약이면 `_finished()`에서 그 목록도 검사한다.

확인한 방법: `SweepBase`, 가격 `9900,19000`, repeat 1, 기본 대역 응답으로 실행했다. 두 번째 자식의 실제 `run()`이 반환한 직후 그 폴더에 다음 `P999.json` 하나를 추가했다. 네트워크나 스레드는 사용하지 않았다.

```json

```

### R2. 중간 | skills/founder-consumer/jev.py:1144 | 집계 단계 파일 오류는 전체 sweep을 중단한다

문제: 변형별 예외 경계는 준비와 자식 실행·이력 읽기에만 있다. `compare()`가 `_summary()`를 호출하는 곳에는 경계가 없다. `_summary()`의 `vw.read()`는 답 폴더 옆 `personas.json`도 읽으며, 이때의 `OSError`가 `main()`까지 전파된다. 정상 변형이 완료됐어도 이번 sweep의 JSON·Markdown 요약을 쓰지 못한다. 앞선 요약이 있으면 갱신되지 않은 파일이 남는다.

제안: 변형별 완료 검사와 요약 생성도 예외 경계에 포함한다. 실패 메시지는 `_why(e, keys)`로 정리하고 해당 변형을 `error`로 바꾼 뒤 나머지 결과를 저장한다. R1처럼 검증한 답에서 가격 튜플을 만들면 가격 분석의 파일 읽기 의존성도 줄어든다.

확인한 방법: `SweepBase`, 가격 `9900,19000`, repeat 1로 실행했다. 첫 자식의 실제 `run()`이 반환한 뒤부터 그 변형의 `personas.json` 열기만 `PermissionError`로 실패시키는 대역을 넣었다. 두 자식의 호출 12건은 완료됐지만 종료 코드 2, `jev-sweep.json` 없음, `jev-sweep.md` 없음이었다. 잠금은 제거됐다. 오류에 넣은 가짜 키는 마지막 `main()` 처리에서 `[key removed]`로 바뀌어 출력 유출은 없었다. 최초 `_look()` 검사 때 읽기를 거부한 1회차 조건과 달리, 완료 뒤 비교 단계의 실패를 확인한 사례다.
